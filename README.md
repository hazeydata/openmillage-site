# OpenMillage site
Static GitHub Pages site built by `python3 build.py` from ../ptax/data into docs/. Serve docs/ via Pages (branch main, /docs).

## Ballot measure 3 baseline page (OM-FL-AMEND3-BASELINE-001)
`python3 amend3.py` (run after `build.py`) writes the page at the slug in `amend3_config.json` (one value; it is currently `fl/amendment-3`), a CSV/JSON of exactly the rows shown, a sitemap entry and an llms.txt line. The heading is `title` from the fact-verified ballot file, and `ballot_number` is shown only as a label. If the ballot file is missing, if `title` or `ballot_number` is absent, or if the title is a label such as "Ballot Number: 3", the build fails closed. The build also fails if any number lacks an adjacent source link, or if forecast or advocacy terms appear outside the quoted official text. Tests: `python3 tests/test_amend3.py`. CI (build-site workflow) runs it after `build.py`, then runs the tests; there is no deploy step. Merging to main is the publish step.

## Texas property tax rate pages (OM-SITE-TX-001)
`python3 statepages.py` (run after `build.py` and `amend3.py`) also writes the Texas hub at `/tx/property-tax-rates/` (canonical), the same hub at `/tx/` (its canonical points at the longer URL; it is not in the sitemap), and one page per county at `/tx/<slug of the CSV county field>/` (254 pages, e.g. `/tx/anderson-county/`), plus sitemap entries, an `llms.txt` line and the two YoY charts in `docs/charts/`.
Inputs are the eleven files under `data/tx/`, pinned in `data/SOURCES.lock` (hazeydata/openmillage@5ceed4f4, calendar years 2021-2025; re-pinned from 2166c845 by OM-DATA-REPIN-001, float noise only). `tx_load` checks every file against the lock before anything is written; a sha256 mismatch, a missing lock entry or a missing file exits non-zero and writes nothing under `docs/tx/`. `tx_stats` also recomputes the county rose/fell/unchanged counts from the CSVs and fails if they disagree with the staged chart counts in `assets/charts/om-2026-11-06/tx-yoy-counts.json`. The NC files under `data/nc/` are pinned in `data/SOURCES.lock` to hazeydata/openmillage@5ceed4f4 (re-pinned from 9578336e by OM-REPIN-LEFTOVERS-001; fire-district unit_basis now cites statute; no rate changes).
The hub and county pages show `county` and `municipal` rows with `levy_component=total` only; school districts have their own pages (next section); special districts are in the data but not on any page (the cover line `TX_COVER_P` says "Special districts: in the data, not on these pages yet."). Rates are the CSV `rate` string verbatim unless it has more than 15 significant digits, in which case it is rounded to 15 significant digits to drop binary float noise (data files unchanged); an empty rate shows "not reported", an absent body "not listed", and Change is `n/a` unless both endpoints are non-empty. Every page carries the 2025 preliminary banner and the per-$100 (`statutory_per_100`) unit callout. Tests: `python3 tests/test_tx_statepages.py` (each check names the AC it covers).
The hub's data-files link (`TX_DATA_URL` in `statepages.py`, shown on `/tx/` and `/tx/property-tax-rates/`) is pinned to this public repo at the OM-REPIN-LEFTOVERS-001 data merge commit (site#25), `https://github.com/hazeydata/openmillage-site/tree/c4c06dc21737d41a3dbfb0ac35b2fc3e3318c6f7/data/tx`, and `SITE_DATA` (the NC folder and FL rollback CSV links) uses the same commit, not `tree/main` (same pattern as the NC pin). It points at this repo rather than hazeydata/openmillage because the product repo is private and its URLs return 404 to visitors. Changing the pin means editing that constant and rebuilding the two hub pages.

## Texas school-district (ISD) pages (OM-SITE-SPECIAL-ISD-001, Phase 2)
`python3 statepages.py` also writes one page per Texas school district at `/tx/<county-slug>/<district-slug>/` (e.g. `/tx/bexar-county/northside-isd/`), with `index.json` beside each page, and the hub `/tx/school-districts/`. The body set is computed by `tx_isds()` from every `body_type=school_district` row of the lock-verified `data/tx/tx-2021.csv` … `tx-2025.csv` (the union of body_ids across the five years; no count is hard-coded). The page lives under the body's home county: the `county` and `taxing_body` of its latest year, slugged with the site's `slug()`. Two bodies sharing a path, an unknown levy component or a duplicate row fails the build before anything is written. A district appears on its home county only (the portions files are not site data).
Each page has a 2021-2025 year table with M&O (`mo`), I&S (`is`) and total, each cell the CSV `rate` string as on the TX county pages (verbatim, 15-significant-digit float-noise rule), linked to that year's Comptroller `source_url` with the data file row and the source file's sha256 in the `title`. A year with no row shows "not listed", an empty rate "not reported". The H1 is the latest published name; a district printed under more than one name (Cumby ISD → Cumby Collegiate ISD) gets a per-year "Name as printed" column. Nothing is summed, ranked or compared across years. Every page carries `TX_PRELIM_P` and `TX_UNIT_P` unchanged, a unique title (`<Name> tax rate 2021–2025`, or `<Name> (<County>) tax rate 2021–2025` when the name is shared), a `Dataset` JSON-LD whose `isBasedOn` is the set of source URLs in the table, and a sitemap entry. `index.json` holds exactly the page's rows: the 17 base keys in CSV order and value, then `preliminary` and `unit_basis` from the provenance file.
The hub lists every district page grouped by home county (filterable, no rates, no ranking, no charts) plus the five source files; each county is a collapsed `<details class=cgroup>` (closed by default; its `<summary>` is the group label, 44 px tall; CSS `TX_HUB_CSS`, scoped to `#isd-groups>details.cgroup`; the filter opens the matching groups) and whose links use the `ul.counties` columns (2 columns at 720 px, 1 at 375); `/tx/property-tax-rates/` and `/tx/` link it (the home page has no Texas links). Each TX county page lists its home districts with links, or "No school district has its home county here in the pinned data." (Loving County). `llms.txt` has one line for the family (URL pattern `/tx/<county-slug>/<district-slug>/`, absent is not zero).
Total-rate chart (AC29, `CHART-SPEC.md` of the dataviz pass): under "Tax rates by year" (after the names note) each page shows an `<h3>` claim and an inline `svg.isd-t` line chart of the `total` rate per year, then the table. The chart is a stdlib string function in `statepages.py` (`isd_trend_svg`, with `ceiling`, `series`, `runs`, `years_txt`, `isd_claim`, `ChartError`, ported from the reference renderer): five fixed year slots, a zero baseline and one ceiling shared by every page (the smallest multiple of 0.25 at or above the largest ISD total, computed at build by `isd_ceiling()`), value labels only at the two ends, the CSV rate strings verbatim. A year with no total row ("not listed") or an empty rate ("not reported") has no point and no segment, never a 0; one note per run of missing years. A year whose provenance `preliminary` flag is `true` (today 2025) gets a hollow point, a dashed segment into it and the word "preliminary". The claim (templates `claim_*` in `TX_ISD_COPY`, values generated from the rows) is byte-identical to the svg's `aria-label`; there is no `<title>` in the svg. Touching "not listed"/"not reported" runs raise `ChartError` and fail the build. Colours are the site's CSS variables; the chart style (`ISD_STYLE`, `ISD_DISPLAY`) is in `site_chrome.CSS` once. The year table and the TX county tables are `table.tx-rates`; their rate cells (`td.num`) never wrap (`white-space:nowrap`, tabular figures) and the cells are tighter at 40rem and below, so the 5-column table fits 375 px. Tests: `python3 tests/test_isd_trend.py` (the 37 reference checks against `statepages` and the pinned data, prints `n/37`; the built-page checks; byte equality of four standalone SVGs with the golden files in `tests/fixtures/isd_trend/`; the nowrap/hub CSS and markup). `tests/browser_tx_layout.py [--width N]` measures chart text size, rate-cell line boxes and page overflow in headless Chrome (run by hand at 375, 390 and 1280; not in CI).

Tests: `python3 tests/test_tx_isd_pages.py` (each check names the AC it covers). `tests/test_tx_statepages.py` covers the hub, `/tx/` and county pages; its AC11 now checks that no TX page mentions `special_district` or Capital Creek and that the raw token `school_district` appears in no TX page's HTML.

## Florida special-district pages (OM-SITE-SPECIAL-ISD-001, Phase 1)
`python3 build.py` also writes the hub `/fl/special-districts/` and one page per Florida independent special district at `/fl/special-districts/<slug>/`, with `index.json` beside each page (exactly that page's rows: the 17 base keys in CSV order and value, then the additive keys, nulls kept). The body set is computed by `sources.fl_bodies()` from every `special_district` row of the merged FL set (`data/special/fl-2025-special-districts.csv` plus the special-district rows of `data/special/fl-2025-alt-sources.csv`; the Pasco cite-only county row is not a special-district row). The slug is the `body_id` without the leading `fl-` and trailing `-special_district`. No count is hard-coded (`tests/test_design.py` guards the generator source against literal page-family counts).
Each body page has one table row per CSV row, grouped by county (`build.body_table`): one `<tbody>` per county, counties A to Z, the county (linked to the county page, with the row's note when it has one) as a `<th scope=rowgroup rowspan=n>` on the group's first row; inside a county the rows run Operating, Okeechobee Basin, Everglades Construction, then any other component in file order (`sources.sd_row_order`; rows are reordered, never relabelled or summed, and `index.json` uses the same order). Columns: levy component (same labels as the county pages, including "(operating + debt, combined)"), the rate as on the county pages (`float(rate):.4f` mills) and a link to the row's `source_url` with its sha256 in the `title` of the short code. The table carries explicit ARIA roles (`table/rowgroup/row/columnheader/rowheader/cell`) because at 40rem and below `table.sd-rates` (CSS in `site_chrome.py`) stacks each county into a block: county, then one line per levy with the rate right-aligned, the source under it. `tests/browser_fl_layout.py` checks the 375 px layout in headless Chrome (run by hand; not in CI). Rates are never summed, ranked or estimated; a county with no row is not listed. The SFWMD page also shows footnote 3 of `data/ref/fl_special_district_footnotes.md` (with the same citations as the Amendment 3 page). Every body page and the hub carry the computed coverage sentence and the open counties from `data/special/tacd_county_status_open.csv` as "not yet sourced" (a county with status `partial` is named on its own line as partial, not as not yet sourced; see the next section). The hub lists each body once (filterable by name or county, ordered by displayed name, case-insensitive, a leading "The " ignored, no rates). County pages link each special-district row to its body page and to the hub; the home page links the hub; `llms.txt` has one line for the page family; every page is in `sitemap.xml` with a `Dataset` JSON-LD whose `isBasedOn` is the set of source URLs on that page.
Page H1 is the body's published `taxing_body` (after `display_name()`). Bodies printed under more than one name take their H1 from `data/ref/fl_special_body_h1.csv` (`body_id,h1`), a site-authored override file (not a data file, so not in `data/SOURCES.lock`; `data/ref/` is outside the lock check). The pick must be one of that body's published names; the other names are listed under "Also printed as". A pick that is not a published name, a pick for an unknown body, or a multi-name body without a pick fails the build before anything is written.

## Florida hub /fl/ (OM-FL-COVERAGE-001)
`python3 build.py` also writes the Florida hub `docs/fl/index.html` (canonical `https://openmillage.com/fl/`; the home page is unchanged apart from one link to it). It links every Florida county page (`/fl/2025/<slug>/`, one per county label in `data/fl-2025.csv`, including the four multi-county city labels such as Flagler/St. Johns) and the Florida sections `/fl/special-districts/`, `/fl/amendment-3/` and `/fl/rolled-back-rate/`. Coverage table: one row per county label, with the county's independent special-district status computed by `sources.fl_hub_status()` from the merged FL rows and the pinned status file `data/special/tacd_county_status_open.csv`. The statuses are: sourced (n bodies); sourced (n bodies, <document kind>) for a county whose only special-district rows come from the alt-sources file, where the kind (water management district document or county property appraiser document) is read from `source_agency` by `sources.alt_kinds()`; partial (n bodies sourced), with the recorded reason, for status `partial`; not yet sourced, with the recorded reason quoted verbatim from the status file; none published yet for a checked county with no row; and a multi-county city label. Above the table, the coverage sentence and the "counties with rows" line (TACD-file counties vs alt-only counties) are computed. No count is written in code or copy. The hub shows no rate, total, rank, estimate or chart (OQ-5), and it carries "absent is not zero".

The coverage sentence's alt tail now has one sentence per document kind: county property appraisers (the kept `FL_SD_COPY` wording) and water management district documents.
